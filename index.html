Task 1: Drawing Single-Color Triangles

For Task 1, the goal was to create a fast way to rasterize a single triangle, defined by points \[(x_0, y_0), (x_1, y_1), (x_2, y_2) \] without any attempts at subsampling. To do this, I first had to define the bounding box of the triangle. This was done by taking the minimum and maximum of the x and y coordinates from the provided vertices, and then restricting the bounding box to the screen buffer dimensions (width x height).

With the bounding box defined, the next step was to iterate over every integer pixel coordinate and check whether the pixel was inside the triangle using the line side test: \[L_i(x, y) = -(x - x_i)(y_{j} - y_i) + (y - y_i)(x_{j} - x_i)\] This test was conducted on the center of the pixel, which is a (0.5, 0.5) offset from the pixel coordinates. If the pixel is within the triangle, checked both in the clockwise (\(L_i ≤ 0\)) and counterclockwise direction (\(L_i ≥ 0\)), then the pixel was filled in with the specified color.

My algorithm tests every pixel within the bounding box exactly once, testing at each pixel if the center is within the triangle. Since no pixels outside the bounding box are evaluated, the runtime complexity is proportional to the pixel area of the bounding box of the triangle. With the screen boundary clamp, the algorithm is equal to or slightly better than a standard bounding box rasterizer.

Task 2: Antialiasing by Supersampling

In many cases, the triangle does not completely encapsulate the pixel. Instead, it occupies only a section of the pixel. If only one sample point is used, then this detail may be missed, and the pixel will not be colored. This results in jagged edges on what should be straight triangle edges, which is known as aliasing. Supersampling is the process of using multiple sample points per pixel when doing rasterization. These sample points can be averaged to get a partial shading of the pixel, creating the appearance of a more straight edge as the jagget edges are no longer as pronounced. Therefore, we can use supersampling as a way of antialiasing the generated images.

The antiliasing algorithm required a few changes to the overall code. First, the sample buffer had to increase in size proportional to the sample rate, ensuring that all samples will be able to fit within the buffer. This did require changes to traversal of the sample buffer as indices now had to account for the 'extra' points introduced by the increased sample rate.

For the rasterization algorithm, there were two main changes: the first was the aforementioned traversal of the sample buffer, as each sample had to be checked to determine if the sample was within the triangle. The next was resolve_to_framebuffer(), which had to be modified to average the samples to get the final color value of the pixel.

Task 4: Barycentric coordinates

Bartcentric coordinates (\(\alpha, \beta, \gamma\)) represent a point P inside a triangle as a weighted combination of the vertices A, B, and C. \[ P = \alpha A + \beta B + \gamma C \] with the restriction that \[ \alpha + \beta + \gamma = 1 \] This representation of coordinates within the triangle allows for smooth interpolation of vertex attributes across the interior of a triangle. In our case, this allows us to interpolate the color of the interior pixels based on the color of the vertices. Task 5: "Pixel sampling" for texture mapping

Pixel sampling is a process used for mapping textures onto objects. More specifically, we want to map continuous, normalized 2D texture coordinates \( (u, v) \) to the integer texel coordinates \((t_x, t_y)\) on a texture map. To see why this is necessary, let's start with some 3D object located at (x, y). The surface on the object is complicated, but it can be mapped using some matrix to a 2D plane in texture coordinates \( (u, v) \). Now, we want to map a texture to this 2D plane. This requires sampling across the texture coordinates, and converting it into the texel coordinate space in the texture map to get details on color, displacement, and other attributes.

There are a couple of algorithms that accomplish pixel sampling, each with their own tradeoffs. The first is nearest sampling, which converts the normalized texture coordinates to the texel coordinates \( (t_x = u * width, t_y = v * height) \), rounds the result to the nearest integer, which selects the closest texel. Another algorithm is bilinear sampling, which uses the same conversion between texutre coordinates to texel coordinates, but instead of rounding to the closest texel, it linearly interpolates between the 4 closest texels.

Nearest sampling begins to fail at steep angles, as a single texel may cover many screen pixels. Nearest sampling creates jaggies as neighboring pixels are likely to round to the same texel. On the other hand, bilinear sampling blends between texels, solving the jagged edges that comes from nearest sampling, instead creating smooth color transitions.

Task 6: "Level Sampling" with mipmaps for texture mapping

Level sampling is the process of selecting the appropriate mipmap level to downsample textures when applying textures to objects far away. When an object is far away (minification), a single screen pixel may cover multiple different textures or colors, which can lead to aliasing artifacts. However, a mipmap of the texture, which contains multiple versions of the texture at original to low resolutions, can be used to select the correct resolution. Now when the low resolution texture is applied, the artifacting is not as noticeable. If the level sampling method is L_NEAREST, the algorithm first begins with by calculating the mipmap level according to the equation \[ \log_2 \left( \max \left( \sqrt{\left(\frac{du}{dx}\right)^2 + \left(\frac{dv}{dx}\right)^2}, \sqrt{\left(\frac{du}{dy}\right)^2 + \left(\frac{dv}{dy}\right)^2} \right) \right) \] where \( \frac{du}{dx}, \frac{du}{dy}, \frac{dv}{dx}, \frac{dv}{dy} \) are the change in texture coordinates when stepping 1 pixel in the x and y directions respectively. Next, L is rounded to the nearest integer, and is used by the Pixel Sampling Method (psm) to select which level of the mipmap to sample from.

There are clear tradeoffs across these different methods used in the assignment for sampling. Supersampling is very effective as an anti-aliasing tool, but it scales linearly in both memory and time complexity, making it expensive to use. PIxel sampling incurs no memory tradeoff, and is only slightly more expensive computationally compared to regular rasterization. However, when dealing with minification, it is not effective at anti-aliasing. Level sampling requires just 33% more memory and does not incur a signifcant computation cost, making it an extremely useful tool at eliminating aliasing and artifacts in textures.
